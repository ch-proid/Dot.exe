단계마다 거치는 테스트

한 번에 한 단계만 만든다. 단계가 끝나면 아래 세 차례를 순서대로 거치고, 사람이 승인해야 다음 단계의 코드를 쓴다. 배속은 tick을 더 자주 돌리는 것이고 tick 하나의 계산은 바꾸지 않는다.

1차 · 에이전트 배속 테스트
  • npm run check 전체 (타입, 테스트, 번역 키)
  • 화면 없이 시뮬레이션을 수천 tick 돌리는 시나리오
  • 규칙 위반, 예외, 수치 발산을 찾는다
2차 · 브라우저 배속 테스트
  • 메인 에이전트가 Chrome에 실제 화면을 띄운다
  • ?speed=8 같은 배속으로 돌려 본다
  • 화면, 콘솔 오류, 조작, 한국어 · 영어를 확인한다
3차 · 사람 테스트
  • 단계마다 Game/Docs/tests/에 체크리스트를 만든다
  • 사람이 직접 해 보고 항목별로 판정한다
  • 재미와 느낌에 대한 관문은 사람만 판정한다

코드 쓰기 전

기반 정리

정본 32절이 구현 전에 준비하라고 한 문서 세 개와 개발 환경을 만든다. 모바일 출시가 목표가 됐으므로 정본 30절의 “1차 플랫폼: Windows 데스크톱”도 여기서 고친다.

만드는 것
  • Game/Docs/current/CORE_GAME_RULES.md 결정사항 v1.1의 규칙을 정식 원본으로
  • Game/Docs/current/ARCHITECTURE.md 시스템 책임, 의존 방향, tick 24단계, 이벤트, 저장 구조
  • AGENTS.md에 개발 규칙 추가 (덮어쓰지 않는다)
  • git init, Vite + TypeScript(strict) + Vitest
  • 커밋마다 타입 검사 · 테스트 · node Locale/check.mjs
모바일로 바뀌며 정할 것
  • 화면은 세로 고정. 1080×1920 기준, 216×384 논리 화면을 safe area 안에 9:16 비율로 배치하고 남는 영역은 CRT 케이스/터미널 여백으로 처리한다
  • 입력은 터치가 기본. F1~F5는 연출로만 남기고 탭 버튼으로 연다
  • 성능 기준 기기. 3~4년 된 중급 안드로이드 한 대를 정한다
  • 웹 기술을 앱으로 싸는 도구. Capacitor를 권한다
끝났다고 보는 기준
  • 빈 화면이 npm run dev로 뜬다
  • 테스트 하나가 CI에서 통과한다
  • 정본 30절과 명세서 머리말의 플랫폼이 고쳐졌다
1
Milestone 1 · 첫 관문

시뮬레이션 코어

명세서 #61이 가장 먼저 검증하라고 한 장면 하나를 만든다. 한 점이 먹이를 찾아 움직이고, 먹고, 분열하고, 먹이 위치를 바꾸면 무리의 흐름이 달라진다. 이 장면이 재미없으면 기획을 더 키우지 않는다.

만드는 것
  • 고정 스텝 루프(20Hz), 렌더 보간, PauseController
  • Vec2, SpatialHash, SeededRandom 두 벌
  • Cell · LifeMode · Health, 부드러운 떠돌이 운동, 경계
  • Nutrient Field (확산 · 감쇠 · 벽)
  • 대사와 에너지 분배, 굶주림, 분열, 사망
  • 점 렌더러와 FEED 터치 입력
자동 테스트
  • 에너지가 모자라면 분열하지 않는다
  • 넘친 에너지가 SYSTEM ENERGY로 새지 않는다
  • 사망 예정 세포는 분열하지 않는다
  • 갓 태어난 세포는 성숙 나이와 준비 시간을 모두 채운다
  • 최고 속도를 넘지 않고 경계를 벗어나지 않는다
  • 같은 시드, 같은 입력이면 결과가 같다
관문 · 직접 해 보고 판단

프로토타입도 본편 P-01과 같은 조건으로 시작한다. Chemotaxis OFF에서 가까운 FEED·분열을 검증하고 P-01 완료 지점에서 Chemotaxis를 지급한 뒤 전후 차이를 확인한다.

Milestone 2

연구 · 특성

플레이어의 선택이 화면 속 행동을 바꾸기 시작한다.

만드는 것
  • ResourceService (SYSTEM ENERGY · DATA · NUTRIENT RESERVE)
  • 연구 10개 데이터와 ResearchService
  • 전역 Trait Loadout, 발현 부하 Safe 100 / Hard 125
  • Modifier 재계산 (더하기 먼저, 곱하기 나중, 누적 없음)
  • Toxin Field, Signal Field
  • 연구 화면. 글은 모두 Locale 키로
자동 테스트
  • 선행 연구가 없으면 살 수 없고, 자원이 모자라면 차감되지 않는다
  • Safe 초과는 허용, Hard 초과는 거부
  • 특성을 여러 번 켰다 꺼도 능력치가 쌓이지 않는다
  • Chemotaxis를 켜면 평균적으로 영양이 짙은 쪽으로 간다
  • 연구 데이터의 키가 모두 en.json에 있다
끝났다고 보는 기준
  • 연구를 하나 켤 때마다 눈에 보이는 행동이 달라진다
  • 최초 세포가 계속 분열해도 첫 연구 비용에 닿는다

Milestone 3

프로토콜

첫 생존 실험. 준비하고, 버티고, 실패하면 체크포인트에서 다시 한다.

만드는 것
  • Protocol 상태 기계 (Idle → Preparing → Running → Completed / Failed)
  • 목표 타입과 판정 (실패 → 성공 → 보상 순)
  • Rapid Bacteria: 영양을 먹고 증식, 약한 독성
  • PURGE, 3차 검토 D절의 수치 채우기
  • 체크포인트(Preparing 진입 시), GAME OVER, 전체 로드
  • P-01 · P-02 · P-03 데이터, P-01 보상으로 Chemotaxis 지급
자동 테스트
  • 수동 시작과 자동 시작이 같은 전환을 거친다
  • 실패하면 체크포인트 이후에 산 연구와 쓴 자원이 함께 돌아간다
  • 마지막 tick에 전멸과 시간 종료가 겹치면 실패다
  • 필요 개체 수가 시작 개체 수와 무관하다
  • 실험 중이 아닐 때 전멸하면 세포 하나가 다시 생긴다
  • 실험 중에는 연구 구매와 특성 변경이 거부된다
끝났다고 보는 기준
  • P-02를 PURGE만으로도 어렵게 넘을 수 있다
  • 방어 연구 셋 중 어느 것을 골라도 통과 경로가 있다
  • 밀집 세포 300 + 세균 300에서 끊기지 않는다

Milestone 4 · MVP 관문

메일 · 서사 · 저장

여기까지가 MVP다. 이 관문을 넘지 못하면 5단계의 큰 콘텐츠 작업에 들어가지 않고 1~3단계로 돌아가 고친다.

만드는 것
  • MailService, 메일 8~10개 (한국어 · 영어)
  • Observation → Narrative 조건 → Mail 흐름
  • DiscoveryService와 DATA 즉시 지급
  • SaveData v1, Campaign 1슬롯, Rolling Autosave 3세대, Protocol Checkpoint, ProfileData
  • HUD, 메일 화면, Briefing → 제한시간 Preparing → Running 흐름, 일시정지 규칙, 개발자 디버그 패널
  • 한글 픽셀 폰트 선정과 실제 크기 확인
자동 테스트
  • 통합 흐름 하나: 새 게임 → 먹이 → 연구 → 프로토콜 → 보상 → 메일 → 저장 → 로드
  • 같은 저장에서 같은 입력으로 진행하면 결과가 같다
  • 이미 실행한 프로토콜 액션이 로드 뒤 다시 실행되지 않는다
  • 한 번만 오는 메일이 두 번 오지 않는다
  • 직접 일시정지한 상태에서 메일을 닫아도 재개되지 않는다
관문 · 다른 사람에게 시켜 본다

  • 첫 플레이 5~7시간, 읽을 수 있는 UNKNOWN 메일은 후반에만
  • 저장 형식이 바뀌었다면 v1 → v2 변환 테스트가 있다

앱으로 만들기

모바일 포장

웹 기술로 만든 게임을 Capacitor로 싸서 안드로이드와 iOS 앱으로 만든다. 게임 규칙은 건드리지 않고 presentation과 input만 바뀌어야 한다. 다른 곳을 고쳐야 한다면 구조가 새고 있다는 신호다.

만드는 것
  • Capacitor 프로젝트, 앱 ID (예: com.이름.dotexe), 버전 규칙
  • 터치 조작: 탭으로 FEED, 길게 눌러 PURGE 범위, 실수 방지 확인
  • 노치·홈 바 safe area, 세로 고정, 1080×1920 기준 9:16 CRT 화면, 18:9·19.5:9·20:9·3:4 적응형 shell
  • 앱이 뒤로 가면 Pause, 돌아올 때 밀린 시간 처리 없음
  • 저장 위치를 앱 전용 저장소로, 쓰기 실패 시 이전 저장본 보존
  • 아이콘, 스플래시, 기기 언어에 따른 한국어 · 영어 선택
확인할 것
  • 기준 안드로이드 기기에서 세포 300 + 적 300
  • 작은 화면에서 한글 메일 본문이 읽힌다
  • CRT 효과를 꺼도 적 · 감염 · 휴면이 구분된다
  • 30분 연속 실행 시 발열과 배터리
  • 전화가 오거나 앱을 강제 종료해도 저장이 깨지지 않는다
준비물
  • 안드로이드: Android Studio. Windows에서 된다
  • iOS: Xcode가 필요하고 Xcode는 Mac에서만 돈다

지금 개발 환경은 Windows다. iOS 빌드는 Mac을 구하거나 Codemagic, GitHub Actions의 macOS 러너 같은 클라우드 빌드를 써야 한다. 이 결정은 5단계가 끝나기 전에 해 둔다.

심사 · 출시

두 스토어의 심사 기간이 다르므로 둘 다 통과시킨 뒤 같은 날 공개한다.

순서
  • App Store 심사 제출. 출시 방식은 “수동 출시”로
  • Google Play 프로덕션 제출
  • 둘 다 승인되면 같은 날 공개
  • Play는 단계적 출시로 일부에게 먼저 열고 충돌을 본다
반려되기 쉬운 곳
  • 심사자가 첫 화면에서 무엇을 할지 몰라 “기능 없음”으로 판단. 심사 메모에 조작법과 P-01까지 가는 길을 적는다
  • 엔딩의 “시스템 종료”가 실제로 앱을 끄면 충돌로 보인다. 연출일 뿐 타이틀로 돌아간다 (정본 29절)
  • 레퍼런스 이미지에 있던 실제 회사 · 서비스 이름이 화면이나 스크린샷에 남아 있으면 안 된다
  • 스크린샷이 실제 화면과 다르다
출시 뒤
  • 첫 주에는 충돌 보고와 리뷰를 매일 확인
  • 저장 형식을 바꾸는 패치에는 반드시 변환 코드와 테스트
  • 새 언어는 Locale에 JSON 하나와 스토어 설명 한 벌
  • Apple 계정은 해마다 갱신. 끊기면 앱이 내려간다

1,500원의 행방

한 번 팔릴 때 손에 남는 돈의 대략적인 크기다. 두 스토어 모두 소규모 개발자에게는 수수료 15%를 적용한다. Apple은 Small Business Program에 따로 신청해야 하고, Google은 연 매출 100만 달러까지 자동이다. 부가세 처리와 소득세는 사업자 여부에 따라 달라지니 출시 전에 세무 상담을 한 번 받는 편이 낫다.

고정비는 Apple 연 $99와 Google 가입비 $25다. Mac이나 클라우드 빌드를 쓰면 그 비용이 더해진다. 첫해 계정 비용만 놓고 보면 150부 남짓 팔리면 메워진다.
