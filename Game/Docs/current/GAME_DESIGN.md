# Dot.exe 상세 기획서

> 버전: 0.4 (`CORE_GAME_RULES.md` v1.3 반영)  
> 장르: 생명 시뮬레이션 / 생존 디펜스 / 연구 트리 / 서사형 인크리멘탈  
> 시대 배경: 1990년대 초반의 가상 생물학 연구소  
> 핵심 미감: 단색 CRT, 오래된 연구용 터미널, 픽셀 UI, 제한된 녹색 계열  
> 작품명: `Dot.exe` / 극중 프로그램명: `Dot.exe`  
> 출시 대상: Google Play · App Store. 유료 다운로드 ₩1,500, 인앱결제·광고·데이터 수집 없음. 세로 화면, 터치 조작 (TypeScript + Canvas/WebGL을 Capacitor로 감싼다)

`Dot.exe`는 작품명과 극중 시스템명 모두에 사용한다. 플레이어가 연구실 컴퓨터에서 실행하는 프로그램도 `Dot.exe`다.

이 문서는 게임의 방향과 경험을 설명한다. 판정 공식, 처리 순서, 저장 범위처럼 구현 결과를 좌우하는 규칙의 정본은 프로젝트 루트의 `CORE_GAME_RULES.md`이며, 이 문서와 어긋나면 그쪽을 따른다. 본문에서 `결정 N절`은 `CORE_GAME_RULES.md`의 N절을 가리킨다. 본문의 수치는 따로 밝히지 않는 한 예시이거나 플레이테스트 전 초기 밸런스 값이다.

## 1. 한 줄 정의

1990년대 초 연구실의 낡은 컴퓨터를 통해 정체불명의 세포 배양 실험을 수행하고, 점점 가혹해지는 생존 실험에 대비해 세포를 진화시키던 플레이어가 자신이 키워온 존재들이 단순한 세포가 아니었음을 깨닫게 되는 실시간 생명 시뮬레이션 게임.

---

## 2. 게임이 주는 감정

게임의 감정 흐름은 다음 순서로 설계한다.

1. **증식의 만족감**  
   한 점에서 시작한 세포가 둘, 넷, 수십 개로 늘어난다.

2. **관찰의 재미**  
   세포가 먹이를 찾고, 모이고, 흩어지고, 위험을 피하며 실제 생명체처럼 움직인다.

3. **대비의 긴장감**  
   다음 실험까지 남은 시간 안에 어떤 연구와 특성을 선택할지 고민한다.

4. **발견의 쾌감**  
   새로운 적응, 특이 개체, 군집 행동이 나타난다.

5. **불안감**  
   세포가 플레이어가 명령하지 않은 행동을 시작한다.

6. **관계의 역전**  
   플레이어가 세포를 관찰하던 게임이, 세포가 자신의 세계와 플레이어를 관찰하는 이야기로 바뀐다.

7. **철학적 여운**  
   “이 세계의 규칙을 누가 바꾸는가?”라는 질문이 게임 바깥의 플레이어에게 돌아온다.

## 3. 핵심 디자인 원칙

### 3.1 숫자가 아니라 행동이 성장해야 한다

연구 보상은 `생산량 +10%`보다 새로운 행동을 우선한다.

예:

- 영양분을 감지한다.
- 위험에서 멀어진다.
- 서로 붙어 군집을 만든다.
- 감염된 개체를 격리한다.
- 적을 둘러싸 제거한다.
- 반복되는 위협을 기억한다.
- 자극이 오기 전에 대응한다.

수치 보정은 보조 수단이며, 주요 연구 노드는 가능한 한 화면에서 즉시 보이는 행동 변화를 만든다.

### 3.2 세포는 직접 조종하지 않는다

플레이어는 세포를 RTS 유닛처럼 클릭해 이동시키지 않는다.

플레이어가 조절하는 것은 다음이다.

- 영양분
- 화학 신호
- 환경값
- 활성 특성
- 긴급 정화
- 실험 조건

세포는 이 조건에 반응해 스스로 움직인다.

### 3.3 타일 기반 이동을 사용하지 않는다

세포는 배양 공간 전체를 연속적인 2D 공간으로 사용한다.

각 세포는 실수 좌표와 속도를 가진다.

- `positionX: float`
- `positionY: float`
- `velocityX: float`
- `velocityY: float`

이동은 상하좌우나 8방향 단위가 아니다.

영양 농도, 위험, 군집 결속, 충돌 회피, 신호, 무작위 운동 등 여러 힘의 합으로 방향이 결정된다.

### 3.4 연구는 곧 생명체의 성격이다

플레이어는 단순히 “강화 수치”를 올리는 것이 아니라 어떤 생존 방식을 가진 생명체를 만들지 선택한다.

예:

- 빠르게 움직이고 침입자를 추적하는 군집
- 이동은 느리지만 강하게 뭉치는 방어 군집
- 환경 변화에 민감하지만 빠르게 적응하는 군집
- 생산은 느리지만 극한 환경에서 살아남는 군집

### 3.5 스토리는 게임 시스템 안에서 진행한다

별도의 컷신보다 다음 수단을 우선한다.

- 연구소 메일
- 시스템 로그
- 예상과 다른 세포 행동
- 분석 화면의 이상 결과
- UNKNOWN 메일
- 플레이어가 이미 사용해 온 시스템의 의미 변화

## 4. 세계관

시대는 1990년대 초반이다.

국가와 실제 기관은 명시하지 않고 가상의 생물학 연구소를 사용한다.

플레이어는 프로젝트 총책임자가 아니라 배양 시스템을 운용하는 연구원이다.

처음 전달받는 설명은 단순하다.

> 컴퓨터에 연결된 자동 배양 장치를 이용해 세포 군집의 생존성과 적응 능력을 연구한다.

플레이어는 화면 속 점이 실제 배양 장치 안의 생물 세포를 컴퓨터가 시각화한 것이라고 생각한다.

실제 프로젝트의 목적은 다음에 가깝다.

> 컴퓨터 환경 안에서 생명 현상을 시스템화하고, 외부 개입 없이 스스로 유지·적응·진화하는 인공 생명 시스템을 만든다.

플레이어가 보는 세포는 현실의 세포를 카메라로 보는 것이 아니라, 컴퓨터 안에서 작동하는 인공 생명 개체다.

이 사실은 초반에 설명하지 않는다.

# 5. 핵심 게임 루프

```text
세포 유지·증식
        ↓
에너지 생산
        ↓
연구 / 특성 해금
        ↓
다음 실험 분석
        ↓
활성 특성 구성 / 환경 준비
        ↓
실험 시작
        ↓
감염·기아·저산소·독성 등 위협 발생
        ↓
세포의 자율 대응 + 플레이어 개입
        ↓
생존
        ↓
DATA / 새로운 현상 / 연구 해금
        ↓
더 복잡한 세포 생태계
```

게임에는 항상 “다음에 무엇을 대비해야 하는가”가 존재해야 한다.

# 6. 메인 배양 화면

초기 화면은 거의 비어 있다.

```text
┌─────────────────────────────┐
│                             │
│                             │
│             ·               │
│                             │
│                             │
└─────────────────────────────┘
```

점 하나가 최초 세포다.

세포 하나는 다음과 같은 값을 가진다.

- 위치
- 속도
- 내부 에너지
- 나이
- 마지막 분열 시각과 분열 진행도
- 스트레스
- 생애 상태(LifeMode): Active / Dividing / Dormant / Dead
- Health (0.0 ~ 1.0)
- 감염 상태
- 군집 ID (군집에 속한 뒤에만)
- 신호 감지 상태

생애 상태, Health, 감염은 서로 독립된 축이다. 손상은 별도 상태가 아니라 Health로 표현하므로 `휴면 + 낮은 Health + 감염`, `분열 중 + 손상` 같은 조합이 가능하다. (결정 11절)

활성 특성은 세포마다 따로 갖지 않는다. 배양체 전체가 하나의 Trait Loadout을 공유한다. (15장)

화면에서 세포는 작은 점 또는 아주 단순한 픽셀 형태로 보인다.

세포 수가 늘어날수록 그래픽을 화려하게 바꾸는 대신 **움직임의 복잡성**이 커진다.

# 7. 세포 이동

## 7.1 기본 운동

세포는 정지해 있지 않고 약한 불규칙 운동을 한다.

방향은 부드럽게 바뀌며, 프레임마다 무작위로 꺾이는 방식은 피한다.

## 7.2 화학주성

영양분 농도가 높은 방향을 감지해 이동한다.

## 7.3 위험 회피

독성 물질, 감염원, 적성 신호에서 멀어질 수 있다.

## 7.4 거리 유지

세포끼리 완전히 겹치지 않도록 약한 반발력이 작용한다.

## 7.5 부착

부착 특성이 활성화되면 일정 거리 안의 인접한 아군 세포와 가까워지려 한다. 아직 군집이 없는 세포끼리도 작용하며, 이 결속이 군집 형성의 출발점이다. (7.9)

## 7.6 방어 행동

방어 행동 특성이 활성화되어 있으면 침입자를 감지한 세포가 직접 접근한다.

## 7.7 군집 이동

후반에는 개별 세포가 아니라 군집의 중심 이동 경향이 생긴다.

## 7.8 배양 공간 경계

배양 공간은 닫힌 사각형 Chamber다. 반대편으로 이어지지 않는다.

경계 근처에서는 약한 반발력이 작용하고, 세포는 경계 밖으로 나갈 수 없으며, 경계에 닿으면 벽을 향한 속도가 줄어든다.

평소 세포가 벽에 부딪히는 것은 흔한 일이다. 후반의 “경계 발견”(22장 PHASE 5)은 이와 구분되는 별도의 행동이어야 한다.

## 7.9 군집 형성

세포는 처음부터 군집 ID를 갖지 않는다.

부착 특성이 활성화된 상태에서 일정 시간 가까이 머문 세포들이 Cluster를 만든다. 군집끼리 연결되면 병합하고, 충분히 오래 떨어져 있으면 분리한다. (결정 18절)

군집 ID와 Cluster 생성은 MVP 이후 기능이다. MVP의 부착은 끌어당기는 힘만 구현한다.

# 8. 플레이어 개입 수단

FEED, SIGNAL, PURGE, 환경 조작처럼 배양 공간에 작용하는 개입은 시뮬레이션이 흐르는 동안에만 쓸 수 있다. 일시정지 상태에서 위치를 확인하고 안전하게 명령을 넣어 두는 플레이는 허용하지 않는다. (14.2)

## 8.1 FEED

원하는 위치에 영양분을 공급한다. NUTRIENT RESERVE를 소모한다.

영양분은 점 하나가 아니라 주변으로 서서히 퍼지는 농도장을 만든다.

세포는 화학주성을 연구했을 때 해당 방향으로 이동한다. 화학주성이 없는 초반(P-01)에는 세포 가까이에 직접 영양분을 놓아야 한다.

## 8.2 SIGNAL

특정 위치에 화학 신호를 만든다.

연구에 따라 다음을 사용할 수 있다.

- ATTRACT
- DEFENSE
- RETREAT
- ASSEMBLE
- DISPERSE

신호는 강제 명령이 아니다.

신호 감지 능력이 있는 세포만 반응한다.

## 8.3 PURGE

작은 영역의 배양액을 강제로 교체한다.

효과:

- 독성 감소
- 일부 침입자 제거
- 폐기물 감소

대가:

- 아군 세포도 피해를 입을 수 있음
- 에너지 소모가 큼
- 재사용 대기시간 존재

## 8.4 ISOLATE

특정 범위의 세포를 임시 격리한다.

용도:

- 돌연변이 분석
- 감염 개체 분리
- 희귀 세포 보호
- 별도 검사

ISOLATE는 MVP에서 제외한다. 이동 차단, 공격·감염·신호의 통과 여부, 영양·독성의 확산, 비용, 지속 시간, 영역 겹침을 한꺼번에 정해야 하는 기능이므로 전체 캠페인 구현 전에 따로 확정한다.

## 8.5 ENVIRONMENT

전체 환경값을 조절한다.

- TEMP
- PH
- OXYGEN
- FLOW

적에게 불리한 환경을 만들 수도 있지만 자기 세포도 영향을 받는다.

환경 조작은 MVP에 넣지 않는다. P-01~03 어디에서도 온도·pH·산소가 게임 결과를 바꾸지 않기 때문이다.

MVP 이후 처음 넣을 때 TEMP, PH, OXYGEN은 배양 공간 전체에 하나씩 있는 전역 값으로 시작한다. OXYGEN은 세포 전체의 소비량에 따라 줄고 환경 장치가 보충한다. 밀집 군집 내부만 저산소가 되는 지역 산소와 FLOW는 그 뒤다.

# 9. 자원

## 9.1 SYSTEM ENERGY

기본 성장 자원. 세포 각자가 가진 내부 에너지와는 다른 값이다.

획득:

- 세포 대사
- 일부 실험 보상

사용:

- 연구
- 시스템 기능
- 일부 긴급 개입

표시 예:

```text
SYSTEM ENERGY
001824
+12.4 / SEC
```

### 세포 내부 에너지와의 관계

세포는 영양을 먹어 에너지를 만들고, 거기서 유지·이동·활성 행동 비용을 뺀 순생산을 내부 저장과 SYSTEM ENERGY로 나눈다.

```text
NUTRIENT
   ↓
대사 총생산
   ↓
유지 · 이동 · 활성 행동 비용
   ↓
순생산
   ↓
세포 내부 에너지  /  SYSTEM ENERGY
```

- 내부 에너지가 생존 보유량보다 낮은 세포는 순생산을 전부 자기 몸에 쓴다. 굶주리는 세포는 연구 자원을 만들지 않는다.
- 생존 보유량을 넘긴 세포는 순생산의 일부를 SYSTEM ENERGY로 보낸다.
- 생존 보유량, 분열 요구량, 최대 저장량, 회수 비율은 서로 다른 값이다.
- 저장량이 가득 찬 세포도 계속 먹고 대사한다. 저장하지 못한 내부 몫은 버리며 SYSTEM ENERGY로 돌리지 않는다.
- 순생산이 음수면 내부 에너지에서 뺀다.

“내부 저장 한도를 넘친 에너지만 회수”하는 방식은 쓰지 않는다. 분열이 에너지를 계속 소모해 연구 자원이 나오지 않는 상황을 피하기 위해서다. (결정 4절)

## 9.2 DATA

시간만 지나서는 얻지 못한다.

획득:

- 새로운 적 분석
- 새로운 행동 발견
- 실험 성공
- 특이 개체 분석
- 조건부 연구 목표 달성

고급 연구는 SYSTEM ENERGY와 DATA를 함께 요구한다.

발견은 종류별로 한 번만 기록하고, 기록하는 순간 DATA를 지급한다. 미확정 DATA는 두지 않는다. 실험에 실패해 체크포인트를 불러오면 발견 기록과 DATA가 함께 되돌아가므로, 다시 하면서 다시 발견하고 다시 받는다. (결정 8절)

MVP에서는 자동 분석만 쓴다. 플레이어가 직접 조작하는 능동 분석은 MVP 이후로 미룬다.

## 9.3 NUTRIENT RESERVE

먹이 공급(FEED)에 쓰는 제한 자원.

천천히 보충되며 실험 사이의 자원 관리에 쓰인다.

# 10. 세포 생애

```text
탄생
 ↓
영양 탐색
 ↓
에너지 생산
 ↓
성장
 ↓
분열 가능 상태
 ↓
분열
```

환경이 악화되면:

```text
스트레스
 ↓
기능 저하
 ↓
손상
 ↓
사멸
```

여기서 손상은 Health가 떨어지는 것을 말한다. 환경이 나아지면 Health는 회복될 수 있다.

굶주림도 같은 길을 따른다. 내부 에너지가 0이 되면 곧바로 죽지 않고 Health가 줄어들며, 에너지를 되찾으면 천천히 회복한다.

치명적인 피해를 입은 세포는 먼저 사망 예정(PendingDeath)으로 표시되고, 그 tick의 마지막에 사망이 확정된다. 사망 예정 세포는 분열하지 못한다.

사망한 세포는 잔여물을 남긴다.

잔여물이 쌓이면 폐기물과 감염 위험이 증가한다.

# 11. 분열

분열 조건은 기본적으로 다음을 고려한다.

- 내부 에너지
- 성숙 나이
- 재분열 준비 시간
- 스트레스
- 개체 수 상한
- 활성 특성

생애 나이와 재분열 준비 시간은 따로 세고, 분열하려면 둘 다 채워야 한다. 성숙 나이를 넘겼고 마지막 분열(갓 태어난 세포는 태어난 시점) 이후 준비 시간도 지나야 한다. 한 번 성숙한 세포가 에너지가 찰 때마다 곧바로 다시 분열하는 일은 없다.

지역 밀도는 기본 조건이 아니다. 고밀도에서 분열을 멈추는 것은 Density Sensing 연구의 효과이고, 그 연구 없이 과밀해진 군집은 영양 경쟁으로 대가를 치른다. (12장)

분열에는 시간이 걸린다. 비용은 분열을 시작할 때 내고, 도중에 죽어도 돌려받지 않는다.

분열로 에너지가 새로 생기지 않는다. 부모의 내부 에너지에서 분열 비용을 뺀 나머지를 부모와 자식이 반씩 나눠 갖는다. 부모의 나이는 유지되고 자식은 0에서 시작한다. 새 세포는 다음 tick부터 행동한다.

감염이 자식에게 넘어가는지는 감염 종류별로 따로 정한다. (결정 12절)

시각 연출:

```text
·
↓
●
↓
· ·
```

분열 직전 잠깐 밝아지고, 두 개체는 아주 가까운 위치에 생성된 뒤 서로 약하게 밀려난다.

# 12. 개체 수와 과밀

개체 수가 많을수록 무조건 유리하지 않다.

과밀 시 발생:

- 영양 경쟁
- 산소 부족
- 폐기물 증가
- 감염 확산
- 이동 정체
- 대사 효율 저하

플레이어는 연구를 통해 더 높은 밀도의 군집을 유지할 수 있다.

MVP에서 과밀의 대가는 영양 경쟁과 이동 정체로 나타난다. 산소와 폐기물은 MVP 이후에 들어온다. 산소를 처음 넣을 때는 전역 값이므로 “개체 수가 많을수록 전체 산소가 빨리 준다”로 나타나고, 밀집한 곳만 저산소가 되는 표현은 지역 산소를 넣은 뒤에 가능하다.

# 13. 실험 프로토콜

일반적인 웨이브 대신 연구소가 내려보내는 **실험 프로토콜**을 사용한다.

예:

```text
PROTOCOL P-04

BACTERIAL EXPOSURE

Introduce strain B-14
and maintain culture
for 180 seconds.

OBJECTIVES:
- AVOID EXTINCTION
- MAINTAIN POPULATION
  REQUIRED 060
  (FINAL 30 SEC)
```

프로토콜은 단순 적 처치보다 “조건을 견디는 것”을 목표로 한다.

## 13.1 목표

뜻이 모호한 `SURVIVAL RATE` 하나로 모든 실험을 판정하지 않는다. 프로토콜마다 목표를 명시적으로 조합한다.

- Survive Duration
- Population Retention
- End Population
- Avoid Extinction
- Maintain Infection Below
- Maintain Environment
- Observe Autonomous Response

필수 목표는 모두 충족해야 한다(AND). 보너스 목표만 선택이다.

개체 수를 셀 때는 생존 가능 개체를 센다. Active, Dividing, Dormant이면서 Health가 0보다 큰 세포이며 감염 개체도 포함한다. 사망 예정·사망 개체와 배양 공간에서 완전히 제거된 분석 샘플은 뺀다.

Population Retention은 “원래 개체가 살아남은 비율”이 아니라 “개체 수를 필요한 수 이상으로 유지했는가”다. 원래 있던 세포 90이 죽어도 새로 태어난 세포로 필요 개체 수를 채우고 있으면 충족이다.

필요 개체 수는 프로토콜이 정한 참조 개체 수에 비율을 곱해 구하고 절대 최저치보다 낮아지지 않는다. 시작 개체 수는 기준에 넣지 않는다. 적게 시작해 기준을 낮출 수도 없고, 많이 키워 들어간 플레이어가 더 높은 기준을 떠안지도 않는다. 화면에는 비율이 아니라 필요 개체 수(`REQUIRED 060`)를 보여준다. (결정 5.2절)

“마지막 30초 유지”는 평균이 아니다. 그 구간의 모든 판정 시점에서 조건을 채워야 한다.

마지막 순간에 전멸과 시간 종료가 겹치면 실패다. 실패 조건을 먼저 보고, 그다음 성공 조건을 보고, 그 뒤에 보상을 준다.

## 13.2 진행 상태

```text
Idle → Preparing → Running → Completed → 다음 프로토콜의 Preparing (없으면 Idle)

Running → Failed → GAME OVER → 체크포인트 로드 → Preparing
```

프로토콜이 공지되어 준비 타이머가 돌기 시작하는 순간(Preparing 진입)에 체크포인트를 한 번 만든다.

준비 시간이 0이 되면 자동으로 시작하고, 플레이어가 먼저 시작할 수도 있다. 두 경우 모두 같은 전환을 거친다.

실험이 끝나 Completed로 넘어갈 때 남아 있는 위협은 제거한다.

실패했을 때의 처리는 30장에서 다룬다.

# 14. 프로토콜 브리핑과 준비 단계

프로토콜은 **읽는 시간**과 **결정하는 시간**을 분리한다.

### Briefing — 시간 제한 없음
시뮬레이션을 멈추고 목표·알려진 위협·보상·현재 배양 상태를 읽는다. 연구 구매, Trait 변경, FEED/PURGE는 불가하다. `BEGIN PREPARATION`을 누르면 준비가 시작된다.

### Preparing — 제한시간 live planning
Preparing 진입 순간 체크포인트와 준비 타이머를 시작한다. 세포와 자원 생산이 실제로 흐르는 동안 연구, Trait, 증식, 영양 배치를 제한시간 안에 결정한다.

RESEARCH, MAIL, ANALYSIS, SYSTEM 화면을 열어도 준비 타이머와 simulation은 계속 흐르고 남은 시간을 항상 표시한다. OS background만 예외적으로 pause한다.

## 14.1 실험 중에는 연구와 특성 변경이 잠긴다

Briefing은 조회만, Preparing/Idle/Completed는 변경 가능, Running은 변경 불가다. Running 진입 순간 Loadout을 고정한다.

## 14.2 게임 시간과 화면

- Briefing: pause
- Preparing: 화면 전환과 무관하게 simulation/timer 진행
- Preparing 이외 일반 화면: CULTURE 밖에서는 pause
- OS background: pause, 복귀 시 밀린 시간 없음

기본 캠페인에는 오프라인 진행이 없다.

# 15. 연구와 발현의 분리

연구는 “가능성의 해금”이다.

실제로 세포가 사용하는 특성은 활성 특성으로 별도 설정한다.

예:

```text
UNLOCKED TRAITS

✓ CHEMOTAXIS
✓ HARD MEMBRANE
✓ FAST DIVISION
✓ TOXIN SECRETION
✓ CELL SIGNALING
```

모든 특성을 동시에 활성화할 수 없다.

활성 특성 구성(Trait Loadout)은 배양체 전체가 공유한다. 특성을 켜면 기존 세포와 새로 태어나는 세포 모두에게 적용된다.

```text
CULTURE GENOME
      ↓
Trait Loadout
      ↓
모든 일반 세포
```

세포마다 다른 능력을 갖는 것은 이후 mutation, role, phenotypeModifier 같은 별도 구조로 추가한다. 역할 분화와 비대칭 분열 연구는 그때 의미를 갖는다.

---

# 16. EXPRESSION LOAD

각 특성에는 유지 비용이 있다.

```text
EXPRESSION LOAD

████████░░
82%
```

발현 부하에는 한도가 둘 있다.

```text
0 ~ 100      정상
100 초과     과발현 상태
125 초과     활성 불가
```

안전 한도(Safe Limit)까지는 정상 작동한다. 안전 한도를 넘겨도 특성은 켤 수 있지만 과발현 상태가 되어 다음 문제가 생긴다.

- 기초 대사 부담 증가
- 분열 비용 증가
- 스트레스 증가
- 유지 효율 저하

절대 상한(Hard Limit)을 넘는 조합은 아예 켤 수 없다.

무리해서 하나를 더 얹는 선택은 남기되, “연구를 많이 했으니 모두 장착한다”는 플레이는 막는다. 100과 125는 초기 밸런스 값이다. (결정 3절)

# 17. 적과 실험 유형

## 17.1 RAPID BACTERIA

매우 빠르게 증식한다.

```text
x
xx
xxxx
xxxxxxxx
```

초기에 제거하지 않으면 공간을 장악한다.

MVP에서는 약한 독성도 함께 만든다. Hazard Avoidance가 실제로 쓰이는 첫 상황이다.

## 17.2 MOTILE BACTERIA

영양분을 추적하며 아군과 자원 경쟁을 한다.

직접 공격보다 굶김이 위협이다.

## 17.3 PARASITE

아군 세포 내부에 침투한다.

```text
·
↓
⊙
```

잠복 후 세포를 파괴하며 여러 개체를 방출한다.

## 17.4 VIRUS

독립 대사가 없다.

세포를 숙주로 사용해 복제한다.

대응:

- 감염 저항
- 자가 사멸
- 격리
- 검출

## 17.5 FUNGAL COLONY

느리지만 자리 잡으면 영역을 넓힌다.

```text
░░░
░░░░
░░░░░
```

배양 공간 자체를 빼앗는다.

## 17.6 TOXIN TEST

적 개체 없이 독성 물질이 퍼진다.

## 17.7 HYPOXIA

산소 농도가 감소한다.

고대사 빌드에 불리하다.

## 17.8 STARVATION

외부 영양 공급이 차단된다.

저장, 휴면, 저대사 특성이 중요해진다.

## 17.9 THERMAL SHOCK

온도가 급격히 변한다.

## 17.10 COMPLEX PROTOCOL

중후반에는 여러 위협을 합친다.

예:

- HYPOXIA + RAPID BACTERIA
- TOXIN + PARASITE + LIMITED NUTRIENT
- THERMAL SHOCK + VIRUS

MVP에는 화면에서 효과를 확인할 수 있는 연구만 넣는다.

# 19. 숨겨진 EMERGENCE 시스템

플레이어에게 `INTELLIGENCE 72%` 같은 수치는 보여주지 않는다.

내부적으로 다음 요소를 추적한다.

- 기억
- 정보 전달
- 환경 예측
- 집단 조정
- 자율 신호
- 장기 패턴 유지
- 비명시적 행동 생성

여러 계열의 행동 증거가 함께 확인되면 EMERGENCE 상태가 시작된다.

특정 연구 하나가 지성을 만드는 구조는 피한다.

## 19.1 점수가 아니라 행동 증거

EMERGENCE는 계속 쌓이는 점수보다 **고유한 행동 증거(Evidence)**로 관리한다.

```text
MEMORY EVIDENCE
- 동일 위협 재노출 시 반응 변화

COORDINATION EVIDENCE
- 다수 세포가 동일 위협에 집단 대응

PREDICTION EVIDENCE
- 자극 이전 행동 변화

AUTONOMY EVIDENCE
- 외부 Signal 없이 집단 행동 개시
```

같은 행동을 반복하거나 재도전한다고 증거가 끝없이 늘지 않는다. 종류별로 처음 확인된 것만 기록한다.

## 19.2 이력과 현재 능력

- **이력(Evidence):** 한 번 얻으면 특성을 꺼도 사라지지 않는다. 체크포인트를 불러올 때만 그 시점으로 돌아간다. 서사 단계를 여는 데 쓴다.
- **현재 능력(Current Capability):** 지금의 활성 특성과 실제 세포 상태가 결정한다. 이상 행동이 화면에서 실제로 일어나는 조건이다.

이력이 있어도 지금 관련 능력이 꺼져 있으면 그 행동은 일어나지 않는다. 일어나지 않은 행동을 메일이 주장하지도 않는다. (20.1)

## 19.3 여러 계통에서 도달

연구 트리 하나를 강제하지 않는다. 서로 다른 계통에서 같은 종류의 증거를 얻을 수 있게 한다.

- 기억 계열: Adaptive Immunity, Response Conditioning, Persistent Signal
- 협동 계열: Collective Defense, Resource Sharing, Collective Response

캠페인의 요구도 특정 노드가 아니라 행동 계열로 적는다.

```text
다음 중 하나의 고등 집단 행동을 관찰:

- Collective Defense
- Resource Sharing
- Signal Relay
```

대사·방어 중심 빌드도 대체 경로로 엔딩까지 갈 수 있어야 한다. (결정 19절)

F1~F5 표기는 옛 터미널의 연출로만 남긴다. 실제로는 화면의 탭 버튼을 눌러 연다. 키보드가 있으면 숫자키를 보조 단축키로 쓴다. hover에 기대는 UI는 만들지 않는다.

## 20.1 메일은 실제 행동 뒤에 온다

메일이 먼저 현상을 주장해서는 안 된다. 항상 다음 순서를 따른다.

```text
행동 시스템
   ↓
실제 행동 발생
   ↓
관찰 기록 (Observation Record)
   ↓
서사 조건 충족
   ↓
메일 발생
```

프로토콜을 끝냈다는 사실만으로 “자극 전에 움직였다”는 메일이 오지 않는다. 세포가 화면에서 실제로 그렇게 움직였고 그것이 기록된 뒤에 온다.

## 20.2 메일 순서

스토리 메일에는 필요에 따라 다음 조건을 둔다.

- 필요한 관찰 기록
- 먼저 받아야 하는 메일
- 그 메일의 읽음 여부
- 최소 간격

조건이 한꺼번에 충족돼도 깨진 데이터 → 문자 → 단어 → 문장 단계의 메일이 한 번에 쌓이지 않게 한다. (결정 20절)

## 23.2 성공 조건

버티기만 해서는 성공하지 않는다.

```text
전멸하지 않음

AND 폐기물/오염 임계값 이하
```

Autonomous Response는 빌드마다 달라도 된다. 자동 감염 격리, 자율 방어 집결, 자동 휴면 전환, 자원 재분배, 자동 경보 등이 해당하며 특정 연구 하나를 강제하지 않는다.

## 23.3 진입과 실패

시작할 때 영양·독성·신호 필드와 환경값은 표준 조건으로 초기화할 수 있다. 세포 내부 에너지는 그대로 가져간다. 에너지를 비축해 들어오는 빌드도 유효한 전략이지만 비축만으로 위 조건을 모두 채울 수는 없다.

실패하면 다른 프로토콜과 똑같이 체크포인트를 불러와 준비 단계부터 다시 한다. (30장, 결정 22절)

| 5~7시간 | 자율 생명체 완성 및 엔딩 |

위 시간표와 비율은 작가용 페이싱 목표이며 코드 조건으로 쓰지 않는다. 실제 서사 진행은 서사 단계, 필요한 관찰 기록, 먼저 받은 메일, 캠페인 진행으로 결정한다.

초기의 약한 징후와 후반의 명백한 자율 행동을 구분한다. Phase 2의 사전 반응은 “시스템 지연일지도 모르는” 약한 징후이고, 표의 “이상 행동 발견”은 부정할 수 없는 단계다. 4~5시간대의 “첫 접촉”은 깨진 데이터를 말하며, 읽을 수 있는 문장은 그 뒤에 온다. (결정 28절)

`D` → `o` → `t` → `.exe`, `TOUCH TO START`, `Dot.exe booting...` 순서로 진행한다.

## 27.5 언어

이 문서에 예시로 실린 화면 글은 영어판 기준이다. 실제 게임의 글은 모두 `Game/Locale/en.json`과 `Game/Locale/ko.json`에서 가져오며, 한국어판에서는 메뉴·HUD·프로토콜·UNKNOWN의 메일까지 한국어로 나온다. 다른 언어는 JSON 파일 하나를 더해 지원한다. 번역 원칙은 `Game/Locale/README.md`에 있다. (결정 30.1절)

메일 본문이 한글이므로 영문 픽셀 폰트만으로 시안을 확정하지 않는다. 실제 목표 해상도에서 최소 글자 크기, 한글 픽셀 폰트 가독성, 메일 본문, 세포 300개 이상인 화면을 직접 확인한다. (결정 26~27절)

# 30. 게임 오버

배양체가 완전히 사멸하면 전체 초기화하지 않는다.

```text
CULTURE FAILURE

RESTORING
LAST VIABLE SAMPLE...
```

실패 처리는 일반적인 싱글플레이 게임처럼 한다. 전멸이든 필수 목표 미달이든 실험에 실패하면 게임 오버가 되고, 그 프로토콜의 준비 단계가 시작되던 시점의 체크포인트를 통째로 불러온다. 준비 타이머가 처음부터 다시 돌고, 연구·특성 구성·증식을 모두 다시 할 수 있다.

체크포인트를 실험 시작 직전이 아니라 준비 단계 시작에 두는 까닭은, 약한 상태로 실험에 들어갔다 실패했을 때 같은 상태로 되돌아가 막히는 일을 없애기 위해서다.

불러오면 전부 그 시점으로 돌아간다. 세포와 적, 자원, 연구, 특성 구성, 메일, 발견 기록, Emergence Evidence까지 모두다. “남는 것”과 “돌아가는 것”을 나누지 않는다. 실패한 시도에서 받은 메일과 발견은 다시 하면서 다시 얻는다.

체크포인트와 무관하게 남는 것은 엔딩 기록과 모드 해금 정보뿐이다.

이전 프로토콜의 체크포인트도 남겨 둔다. 준비 단계를 다시 해도 넘을 수 없을 만큼 배양체가 무너졌다면 더 앞의 체크포인트를 불러올 수 있다.

## 30.1 실험 중이 아닐 때의 전멸

실험이 진행 중이 아닐 때 세포가 전멸하면 게임 오버로 처리하지 않는다. 같은 `RESTORING LAST VIABLE SAMPLE` 연출과 함께 초기 세포 하나를 배양 공간 중앙에 다시 만들고 자원과 연구는 그대로 둔다.

P-01을 시작하기 전에 첫 세포를 굶겨 죽이는, 처음 하는 사람이 가장 하기 쉬운 실수를 받아 주기 위한 규칙이다. (결정 6~7절)

# 32. 기획 충돌 및 이상 지점 점검

## 32.1 ENERGY 하나로 모든 연구를 해결하면 방치형으로 변한다

대응:

- SYSTEM ENERGY는 성장 자원
- DATA는 실험과 발견 자원

고급 연구는 둘 다 필요하다.

## 32.2 세포가 자율적이면 플레이어가 구경만 할 수 있다

대응:

- 환경 조작
- 먹이 배치
- 신호
- 특성 구성
- 긴급 정화

를 통해 결과에 강하게 개입한다.

## 32.3 연구를 많이 할수록 모든 능력이 동시에 켜지는 문제

대응:

- 연구는 해금
- 발현은 별도
- EXPRESSION LOAD로 동시 활성 제한 (안전 한도 초과는 패널티, 절대 상한 초과는 불가)
- 실험 중에는 특성 구성을 바꿀 수 없음

## 32.4 지성 관련 연구를 선택하지 않으면 스토리가 막히는 문제

대응:

EMERGENCE는 특정 한 노드가 아니라 여러 계통의 조합으로 발생한다.

필수 스토리 조건은 캠페인 진행 중 자연스럽게 충족되도록 구성하되, 플레이어에게 `INTELLIGENCE` 노드를 강제하지 않는다.

입력이 여러 개라는 것만으로 모든 빌드의 도달이 보장되지는 않는다. 그래서 점수 대신 행동 증거를 쓰고, 같은 증거를 여러 계통에서 얻게 하며, 대사·방어 중심 빌드의 대체 경로를 캠페인 설계 때 직접 확인한다. (19장)

## 32.5 매번 공격만 하면 타워디펜스 반복이 된다

대응:

- 기아
- 저산소
- 고온
- 독성
- 자원 경쟁
- 기생
- 복합 환경

을 충분히 섞는다.

질문은 “적을 어떻게 죽이는가?”보다 “이번 환경에서 어떻게 살아남는가?”가 되어야 한다.

## 32.6 세포가 갑자기 메일을 보내면 개연성이 약하다

대응:

세포가 시스템의 텔레메트리 출력 경로를 간접적으로 이용하는 설정을 둔다.

표현 과정도:

깨진 데이터 → 문자 → 단어 → 짧은 문장 → 질문

순으로 진행한다.

## 32.7 플레이어가 왜 프로젝트 정체를 모르는가

대응:

플레이어는 총책임자가 아니라 운용 담당이다.

전체 프로젝트 목적은 제한적으로만 공유된다.

## 32.8 후반 자동화가 플레이 자체를 없애는 문제

대응:

완전 자율화는 최종 프로토콜에 한정한다.

그 전에는 자율성이 증가해도 플레이어의 개입이 계속 필요하다.

## 32.9 반전이 너무 빨리 읽히는 문제

대응:

게임 전반부는 실제로 충분히 재미있는 생명 생존 게임으로 성립해야 한다.

UNKNOWN의 명확한 메시지는 후반부에만 등장시킨다.

# 34. MVP 범위

첫 구현은 전체 캠페인을 만들지 않는다. 스토리가 아니라 다음을 검증한다.

1. 한 점이 살아 움직이는 느낌이 있는가.
2. 세포 수가 늘어날수록 화면이 재미있어지는가.
3. 먹이 위치 조작이 플레이로 느껴지는가.
4. 연구가 실제 행동 변화를 만든다고 느껴지는가.
5. 다음 프로토콜 준비가 전략적 선택을 만드는가.
6. Rapid Bacteria와의 첫 방어가 재미있는가.

## 34.1 포함

- 세포 최대 300
- 공간 필드: Nutrient, Toxin, Signal (Signal은 Alarm Signal 전용)
- 플레이어 조작: FEED, PURGE
- 자원 세 가지: SYSTEM ENERGY, DATA(자동 분석만), NUTRIENT RESERVE
- 연구 10개 (18.7)
- 전역 Trait Loadout과 발현 부하
- Rapid Bacteria
- 프로토콜 3개
- 메일 8~10개, 서사 Phase 1~2. Phase 2 메일은 감염 실험 안내와 방어 연구에 대한 반응으로 한정한다.

## 34.2 프로토콜

**P-01 CULTURE EXPANSION**  
Chemotaxis 없이 시작한다. 가까운 FEED, 불규칙 이동, 대사와 분열이 먼저 재미있어야 한다. P-01 완료 보상으로 Chemotaxis를 즉시 지급·활성화하고, 같은 FEED를 더 먼 곳에 사용했을 때 세포가 스스로 찾아가는 변화를 첫 성장 보상으로 보여준다.

첫 프로토타입도 이 순서를 그대로 따른다. Chemotaxis를 미리 켜지 않으며 OFF 상태의 기본 재미와 ON 이후의 성장 체감을 각각 판정한다.

**P-02 RAPID BACTERIA**  
Rapid Bacteria 최초 투입. 기본 PURGE로도 어렵게 통과할 수 있고 방어 연구가 있으면 유리하다.

**P-03 LIMITED NUTRIENT**  
NUTRIENT RESERVE 보충 속도를 줄이고 Rapid Bacteria가 같은 영양을 먹어 증식하게 해 자원 경쟁을 만든다.

## 34.3 MVP 이후로 미루는 것

- Mutation
- 개별 세포 Trait, 다중 역할 분화
- 환경값(Temperature, pH, Oxygen)과 ENVIRONMENT 조작, FLOW
- 폐기물, CONTAMINATION
- 군집 ID와 Cluster 생성
- 플레이어 SIGNAL (받을 세포가 없다. Signal Detection이 MVP 연구에 없다)
- ISOLATE
- 능동 Analysis
- 사전 반응 메일 (예측 행동이 화면에서 실제로 일어나야 보낼 수 있다)
- Virus, Parasite, Fungus
- 완전한 Emergence 캠페인, UNKNOWN 메일 전체 시퀀스
- 최종 프로토콜

(결정 14~16절, 33절)
